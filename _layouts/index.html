What it does

Structured logging that stays off your hot path

Each card opens its section on the features page.

Off the calling thread

fire() checks the level and pushes the record into a 65,536-slot ring buffer. A background thread formats it and does the I/O.

How the engine works

14 output formats

JSON, NDJSON, ECS, GELF, Logstash, OTLP, MCP, logfmt, CLF, CEF, ELF, W3C, Apache and Log4j XML, chosen per record.

See every format

Native sinks

Records go to os_log on macOS and journald on Linux, and to standard output everywhere else.

Where records go

Redaction

rlg-redact scrubs card numbers, JWTs, bearer tokens, email and IPv4 addresses and AWS keys before a record is written.

What gets scrubbed

OpenTelemetry export

rlg-otlp ships records over OTLP/HTTP to a local OpenTelemetry Collector, which forwards them to your backend.

How export works

Logs for AI agents

rlg-mcp serves log files to MCP clients as four tools, with a triage prompt, over stdio or HTTP.

What agents can ask

Install

A structured record in a few lines of Rust

Initialise once, keep the guard, and fire records from anywhere. rlg needs Rust 1.88 or newer.

  • cargo add rlg
  • cargo install rlg-cli

Security

Checked by more than its own tests

rlg runs its engine under Miri and Loom, fuzzes the inputs it parses, and signs what it releases.

rlg is at 0.0.x and has one maintainer: any release may break your build, and the security page lists what has and has not been checked.
